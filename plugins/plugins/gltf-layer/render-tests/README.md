# gltf render tests

Run them in a Metal build (the layer only has a Metal shader):

```sh
bazel test //plugins:render-tests-gltf --//:renderer=metal --//:plugins=true
```

On macOS the link may need ICU, which Homebrew keeps out of the default library path:
`--linkopt=-L$(brew --prefix icu4c)/lib`.

| Test | What it checks |
|---|---|
| `basic` | A model drawn with a heading and a size in meters. |
| `occlusion-behind-extrusion` | A fill extrusion hides a model behind it, and leaves the models in front of and beside it alone. |
| `occlusion-disabled` | With `model-occlusion: 0` the same model is drawn over the extrusion. |
| `unknown-model` | A feature that names a model that can't be loaded is not drawn, and the tile still renders. |
| `eiffel-tower` | A real model instead of a generated box: the CC0 Eiffel tower (see below), with 38 materials in one mesh, drawn at its true size of 300 m. Rendered at `pixelRatio` 3 (768×960) so the parts of the tower can be told apart. |

`occlusion-behind-extrusion` is a regression test: the layer used to be drawn with a 2D depth state, which the
renderer turns off for every layer above a 3D layer, so nothing could hide a model. Its expected image is the scene
without the hidden model rather than a screenshot of the renderer, so it doesn't depend on the code it tests.

## Updating expectations

The boxes are generated by `../scripts/generate_render_test_models.py`, and the Eiffel tower is prepared by
`../scripts/prepare_eiffel_tower.py` (see below). To record new expected images, run the test binary from the
repository root and inspect every changed `expected.png` before committing it. `-u default` rewrites the expectations
of every test, including the ones that are built another way (`occlusion-behind-extrusion`), so select the tests with
`--filter`:

```sh
bazel build //plugins:render-tests-gltf --//:renderer=metal --//:plugins=true
bazel-bin/plugins/render-tests-gltf --manifestPath plugins/plugins/gltf-layer/render-tests/manifest.json -u default --filter eiffel
```

## The Eiffel tower

`assets/eiffel-tower.glb` is derived from [Eiffel Tower](https://conic.openstreetmap.de/model/4) (revision 3) by n42k,
from the [3D Model Repository](https://conic.openstreetmap.de), which publishes it under the
[Creative Commons CC0 1.0 Universal Public Domain Dedication](https://creativecommons.org/publicdomain/zero/1.0/).
The repository says it was taken from [BlendSwap](https://www.blendswap.com/blends/view/67944). That page returned
HTTP 404 on 2026-10-27, so the repository's license statement is the one that can be checked. CC0 needs no attribution,
but the file names its origin in `asset.copyright`.

The layer only draws the base color factor of a material, and a mesh has 16-bit indices, so the file is not the
original. The source is 10.7 MB with 34 textures and 166,000 vertices, and `../scripts/prepare_eiffel_tower.py` makes the
162 KB, 4,865 vertex file from it:

- It keeps the tower and drops the first-floor railing frame and the guard rail.
- It drops the textures. The frames of the tower are lattice textures with transparent gaps, so each textured material
  gets the average color of the opaque pixels of its texture as its base color factor.
- The units are still meters, the base of the tower is on the ground, and each material is still a primitive.

The script downloads the source, checks it against a pinned SHA-256 and writes the same file every time:

```sh
python3 plugins/plugins/gltf-layer/scripts/prepare_eiffel_tower.py
```

The base colors are linear, as glTF says, and the layer's shader converts them to sRGB before it lights them. The
generators of the other models (`generate_render_test_models.py` and the demo's `generate_models.py`) take their colors
as sRGB, the way they look, and write the linear values.

The layer has one light, which shines from the north-east and from above, and a surface turned away from it gets 32% of
its color. The test looks south-south-west (bearing 200) so that the camera sees the sides the light shines on.
