# Release MapLibre iOS

We make iOS releases to GitHub (a downloadable XCFramework), the [Swift Package Index](https://swiftpackageindex.com/maplibre/maplibre-gl-native-distribution) and [CocoaPods](https://cocoapods.org/). Everyone with write access to the repository is able to make releases using the instructions below.

Each release is published to two Swift package repositories. The `ios-release.yml` workflow dispatches their `release.yml` workflows, which point the binary target at an XCFramework of the GitHub release:

| Repository | XCFramework |
| --- | --- |
| [maplibre/maplibre-gl-native-distribution](https://github.com/maplibre/maplibre-gl-native-distribution) | `MapLibre.dynamic.xcframework.zip` |
| [maplibre/maplibre-ios-with-plugin-api](https://github.com/maplibre/maplibre-ios-with-plugin-api) | `MapLibre.dynamic.plugins.xcframework.zip`, built with `--//:plugins=true` |

Also see the current [release policy](../../release-policy.md).

## Making a release

1. Prepare a PR, see [this PR](https://github.com/maplibre/maplibre-native/pull/3193) as an example. There is no changelog to update, see [release notes](#release-notes).

    - Update the `VERSION` file in `platform/ios/VERSION` with the version to be released. We use [semantic versioning](https://semver.org/), so any breaking changes require a major version bump. Use a minor version bump when functionality has been added in a backward compatible manner, and a patch version bump when the release contains only backward compatible bug fixes.

2. Once the PR is merged the `ios-ci.yml` workflow will detect that the `VERSION` file is changed, and a release will be made automatically.

## Pre-release

Run the `ios-ci` workflow. You can use the [GitHub CLI](https://cli.github.com/manual/gh_workflow_run):

```
gh workflow run ios-ci.yml -f release=pre --ref main
```

Or run the workflow from the Actions tab on GitHub.

## Release notes

The release notes of a release and of a pre-release are generated by the `ios-release.yml` workflow, they are not kept in a file. They list the pull requests that were merged since the previous release, which is the closest earlier `ios-v<X.Y.Z>` tag. Tags of versions with a postfix, such as `ios-v7.0.0-pre2`, are skipped. Only pull requests that change `platform/ios`, `platform/darwin` or the code that all platforms share are listed, with their title, so give pull requests a title that tells developers using the SDK what changed.

To preview the release notes of the current commit, run the following with the full git history and the tags fetched:

```
node .github/scripts/generate-release-notes.ts --platform ios
```
